# 从 1.21.1 升级

本页说明 RenderJS `2101.x`（Minecraft 1.21.1）脚本迁移到 `26.1.2-1.0.0`（Minecraft 26.1.2）时需要改什么。
**事件名基本不变**，破坏点集中在 GUI 上下文、世界渲染和方块实体渲染器。

## 一、破坏性变更一览

| 旧（1.21.1） | 新（26.1.2） | 处理方式 |
|---|---|---|
| `GuiRenderHelper` 全局对象 | 已删除 | 改用事件对象上的绘制方法（`onGuiPreRender` / `onScreenPreRender` / 物品装饰的 `ctx`） |
| `GuiGraphics` 绑定 | 换为 `GuiGraphicsExtractor` | 一般不需要直接引用，绘制用事件对象的方法 |
| GUI `getPoseStack()` 返回 `PoseStack` | 返回 `Matrix3x2fStack`（2D） | `pushPose/popPose` 方法名保留；`mulPose(四元数)` 改为 `rotateDegrees(角度)` |
| 世界渲染里伪造 GUI 上下文（`GuiGraphics.pose = 世界PoseStack`） | 已移除 | 世界/实体/方块实体渲染改用 [世界渲染](世界渲染.md) 方法 |
| `renderSingleBlock(state, pose, bufferSource, ...)` | `renderSingleBlock(state, pose[, light, overlay])` | 去掉 `MultiBufferSource` 参数 |
| `renderLevelItem(stack, pose, bufferSource, ...)` | `renderLevelItem(stack, pose[, light])` | 去掉 `MultiBufferSource` 参数 |
| `renderHitOutline(state, pose, bufferSource, ...)` | `renderHitOutline(state, pose[, entity[, pos]])` | 去掉 `MultiBufferSource` 参数 |
| `RenderLevelStageEvent.Stage` 枚举、`event.getStage()` 返回枚举 | `event.getStage()` 返回字符串 `"submit"`；`RenderJSLevelRenderStage.SUBMIT` | 删除按阶段分支的代码；世界渲染每帧只有一次提交 |
| `RenderJSRenderSystem` 的状态方法（blend/depth/shader/color） | 全部为 no-op | 删除相关调用；渲染状态由 RenderType/渲染管线决定 |
| `RenderJSRenderType.TOP_LAYER_TARGET` 等「永远置顶」RenderType | 普通 vanilla RenderType 别名 | 不再保证置顶；需要特殊层级要用自定义渲染管线（暂未开放脚本注册） |
| 方块渲染支持脚本指定 RenderType / 全局着色 | 全局颜色/RenderType 状态已移除；RenderType 改为每次调用时传入（`renderSingleBlock(..., renderType)`） | 需要透明/穿透时传对应 RenderType（如 `RenderJSRenderType.TOP_LAYER_TARGET`） |
| 方块实体渲染器单阶段 `render(...)` | 两阶段 `createRenderState/extractRenderState/submit` | 脚本用 `RenderJSBlockEntityRenderer` + `setCustomRender((renderer, ctx) => {})` |
| `RegisterBlockEntityRender` 事件里创建自定义 renderer | 事件名不变，`registerOrSwap` 仍在 | 参考[实体与方块实体](实体与方块实体.md)的新写法 |
| 颜色参数 `int` | `long`（`0xAARRGGBB`） | 旧脚本一般无需改动；若报 `Cannot convert ... to int`，写 `0xFF00FF00 | 0` |

## 二、不变化的部分

- `RenderJSEvents` 事件组名与事件名（`onGuiPreRender`、`onGuiPostRender`、`onScreenPreRender`、`onScreenPostRender`、`onLevelRender`、`onLivingPreRender`、`onLivingPostRender`、`RegisterItemDecorations`、`registerBlockEntityRender`）；
- `kubejs.plugins.txt` 与插件注册机制；
- GUI 绘制方法名（`fill` / `hLine` / `vLine` / `drawString` / `drawShadowString` / `drawTexture` / `drawTextureWithSize` / `renderGuiItem`）；
- 物品装饰的注册方式与 `ctx.xOffset/yOffset/itemStack` 字段；
- 3D pose 方法名（`pushPose` / `popPose` / `translate` / `scale` / `mulPose` / `rotationDegreesX/Y/Z`）；
- `PoseStack`、`Mth`、`LevelRenderer` 等绑定名。

## 三、迁移检查清单

1. **替换 `GuiRenderHelper`**：全局搜索，确认每处都在某个 GUI 事件回调内，改成 `event.xxx(...)`。
2. **检查世界渲染**：凡是「在世界渲染事件里调 GUI 绘制方法」的代码，改成 `renderSingleBlock` / `renderLevelItem` / `renderHitOutline`。
3. **删掉阶段判断**：搜索 `RenderJSLevelRenderStage.`、`.getStage()`，删除 `AFTER_ENTITIES` 之类的分支（26.1.2 只有 `SUBMIT`）。
4. **删除 `RenderJSRenderSystem` 调用**：这些调用现在没有效果，留着只会误导。
5. **去掉 `MultiBufferSource` 参数**：`renderSingleBlock` / `renderLevelItem` / `renderHitOutline` 的新签名不再接收。
6. **检查颜色**：所有颜色写满 8 位 ARGB；6 位颜色（`0xRRGGBB`）alpha=0，不会渲染。
7. **方块实体渲染器**：按[实体与方块实体](实体与方块实体.md)迁移到 `RenderJSBlockEntityRenderer`。
8. **物品装饰**：逻辑不变，注意颜色 alpha；注册会在脚本重载时自动重建。
9. **客户端验证**：先跑通 HUD → 世界 → 物品装饰 → 方块实体，逐项排查。

## 四、旧扩展点 / 内部实现变化（给维护者）

| 旧实现 | 26.1.2 实现 |
|---|---|
| `GuiGraphicsMixin` 注入 `GuiGraphics#renderItemDecorations` | 注入 `GuiGraphicsExtractor#itemDecorations`（方法名与参数类型变化） |
| `PoseStackAccessor`（读 pose 栈内部） | 已删除（字段变化且旧代码未使用） |
| `BlockEntityRenderDispatcherMixin`（读私有 renderers） | 已删除，改用公开的 `BlockEntityRenderDispatcher#getRenderer` |
| 6 条 Access Transformer | 全部移除（不再需要） |
| `mixin` 配置里的 `refmap` / `compatibilityLevel: JAVA_17` | 已移除 refmap；`compatibilityLevel` 省略（跟随环境） |
| 依赖 CurseForge 的 KubeJS/Rhino | 改为 `maven.latvian.dev` 的 KubeJS 8 + 其传递依赖 Rhino |
