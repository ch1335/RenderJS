# 快速开始

## 前置条件

- Minecraft 26.1.2 + NeoForge 26.1.2.122+
- [KubeJS](https://kubejs.com/) 26.1.2-8.0.7+（及其前置 Rhino）
- RenderJS `26.1.2-1.0.0`

## 安装

1. 把 `renderjs-neoforge-26.1.2-1.0.0.jar` 放进 `mods/`；
2. 启动一次游戏（客户端），KubeJS 会生成脚本目录。

> 模组双端都会加载，但**所有渲染能力只客户端生效**；渲染事件不要写在服务端脚本里。

## 脚本放在哪里

客户端脚本统一放在 `kubejs/client_scripts/`：

```
实例根目录/（或整合包目录/）
  kubejs/
    client_scripts/
      renderjs_demo.js
```

脚本修改后按 **F3 + T** 重载资源与脚本，无需重启。

## 第一个脚本

```js
// kubejs/client_scripts/renderjs_demo.js
RenderJSEvents.onGuiPreRender(event => {
  event.fill(8, 8, 168, 34, 0xAA000000)                    // 半透明黑底
  event.drawString(Text.ofString('Hello, RenderJS!'), 12, 12, 0xFFFFFFFF)
})

RenderJSEvents.onScreenPreRender(event => {
  event.fill(4, 4, 12, 12, 0xFFFF0000)                     // 任意界面左上角红块
})
```

更多可运行示例见项目根目录的 [`examples/client_scripts/`](../../../examples/client_scripts/)。

## 颜色约定

颜色是 **ARGB 8 位十六进制**，写作 `0xAARRGGBB`：

| 写法 | 含义 | 是否可见 |
|---|---|---|
| `0xFFFFFFFF` | 不透明白 | ✅ |
| `0x80FF0000` | 半透明红 | ✅ |
| `0xFFFF0000` | 不透明红 | ✅ |
| `0x00FF00`（6 位） | 实际是 `0x0000FF00`，alpha = 0 | ❌ 完全透明，不渲染 |
| `0xFF00`（4 位） | 实际是 `0x0000FF00`，alpha = 0 | ❌ |

如果脚本工具提示颜色需要「有符号 int」，可以在字面量后加 `| 0`：`0xFF00FF00 | 0`。
RenderJS 的颜色参数是 `long`，直接写 `0xFF00FF00` 也可以。

## 常用对象

| 用途 | 写法 |
|---|---|
| 文字 | `Text.ofString('hello')`（`Component` 是同义绑定） |
| 资源 ID | 直接传字符串 `'minecraft:textures/gui/...'`；或 `ID.of('ns:path')` |
| 物品 | `Item.of('minecraft:diamond')` |
| 方块状态 | `Blocks.DIAMOND_BLOCK.defaultBlockState()`；多数方法也接受字符串 `'minecraft:diamond_block'` |
| 坐标 | `new BlockPos(x, y, z)` |
| 颜色 | `0xAARRGGBB`（long） |

## 调试

- 输出日志：`console.info('...')` / `console.warn('...')` / `console.error('...')`；
- 客户端日志文件：`run/logs/latest.log`（开发环境）或实例 `logs/latest.log`；
- 脚本报错会显示在 KubeJS 的错误界面/日志中，行号指向你的脚本；
- 修改脚本后按 **F3 + T** 重载，比重启快。

## 常见问题

**Q：画的东西完全看不到？**
先检查颜色 alpha——6 位颜色等于 alpha=0，不会渲染；确认脚本在 `client_scripts/` 下；确认是在事件回调里调用（不能在顶层直接画）。

**Q：报 `Cannot convert 4278255360 to int`？**
旧版本 RenderJS 的颜色参数是 `int`；本版本已改成 `long`，一般不会再出现。若仍出现，把颜色写成 `0xFF00FF00 | 0`。

**Q：事件回调每帧都在执行，会卡吗？**
会。`onGuiPreRender`、`onScreenPreRender`、`onLevelRender` 等回调**每帧触发**，不要在里做复杂计算、遍历大量数据或频繁创建对象；需要缓存的数据放到脚本顶层或事件外。

**Q：服务端脚本里能用吗？**
不能。渲染事件是客户端事件；专用服务器没有渲染上下文。

**Q：物品装饰注册重复了？**
`RegisterItemDecorations` 会在每次资源/脚本重载时重新触发，注册是幂等的（每次重载前会清空）。不要在普通渲染事件里重复注册。
