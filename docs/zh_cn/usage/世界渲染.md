# 世界渲染

适用于 `onLevelRender`（世界几何提交阶段）与 `onLivingPreRender` / `onLivingPostRender`（生物实体渲染）。

## 坐标系

世界渲染使用的是**相机相对坐标**：把 pose 先平移到相机位置，后面所有坐标都相对相机。

```js
RenderJSEvents.onLevelRender(event => {
  const poseStack = event.getPoseStack()

  event.pushPose()
  event.transformerCamera(poseStack)                       // 平移到相机相对空间
  event.transformerToBlockPose(poseStack, new BlockPos(0, 64, 0))  // 再平移到方块位置
  // 此处坐标 (0,0,0) = 方块 (0,64,0) 的西北下角
  event.renderHitOutline(Blocks.DIAMOND_BLOCK.defaultBlockState(), poseStack)
  event.popPose()
})
```

- `event.transformerCamera(poseStack)`：等价于 `translate(-cameraX, -cameraY, -cameraZ)`；
- `event.transformerToBlockPose(poseStack, pos)`：平移到方块坐标；
- `event.getCameraPosition()`：当前相机世界坐标（`Vec3`）。

## 渲染方法

| 方法 | 说明 |
|---|---|
| `renderSingleBlock(blockState, poseStack)` | 渲染方块模型（默认全亮、无染色） |
| `renderSingleBlock(blockState, poseStack, color)` | 整体染色 |
| `renderSingleBlock(blockState, poseStack, color, renderType)` | 染色 + 指定 RenderType（层级/穿透） |
| `renderSingleBlock(blockState, poseStack, color, renderType, packedLight)` | 再指定光照 |
| `renderSingleBlock(blockState, poseStack, color, renderType, packedLight, packedOverlay)` | 全参数 |
| `renderSingleBlockWithType(blockState, poseStack, renderType)` | 不染色、指定 RenderType |
| `renderSingleBlockWithType(blockState, poseStack, renderType, packedLight)` | 不染色 + 光照 |
| `renderSingleBlockWithType(blockState, poseStack, renderType, packedLight, packedOverlay)` | 不染色 + 光照/overlay |
| `renderLevelItem(itemStack, poseStack)` | 以 `GROUND` 姿态渲染一个物品 |
| `renderLevelItem(itemStack, poseStack, packedLight)` | 指定光照 |
| `renderLevelItem(itemStack, poseStack, packedLight, packedOverlay)` | 指定光照/overlay |
| `renderHitOutline(blockState, poseStack)` | 画方块轮廓线 |
| `renderHitOutline(blockState, poseStack, color)` | 指定描边颜色 |
| `renderHitOutline(blockState, poseStack, color, renderType)` | 指定颜色 + RenderType |
| `renderHitOutlineWithType(blockState, poseStack, renderType)` | 指定 RenderType（默认描边色） |
| `packLight(level, blockPos)` | 计算该位置打包后的光照值 |
| `LightCoordsUtil.FULL_BRIGHT` | 全亮光照常量（全局绑定） |

## 颜色

`renderSingleBlock` 和 `renderHitOutline` 都支持直接传 ARGB 颜色做整体染色：

```js
RenderJSEvents.onLevelRender(event => {
  const poseStack = event.getPoseStack()
  event.pushPose()
  event.transformerCamera(poseStack)
  event.transformerToBlockPose(poseStack, new BlockPos(0, 64, 0))

  const state = Blocks.DIAMOND_BLOCK.defaultBlockState()

  // 整体染成红色（乘到所有顶点，包括没有 tint index 的方块）
  event.renderSingleBlock(state, poseStack, 0xFFFF0000)

  // 同时指定 RenderType（例如无深度、穿过地形）
  event.renderSingleBlock(state, poseStack, 0x80FF0000, RenderJSRenderType.TOP_LAYER_TARGET)

  // 描边颜色
  event.renderHitOutline(state, poseStack, 0xFFFF0000)

  event.popPose()
})
```

注意事项：

- 整体染色通过自定义几何提交（`QuadInstance` 顶点色）实现，会以**单一 RenderType** 提交：
  半透明颜色需要配合半透明 RenderType（自定义 pipeline）才会有混合效果；
- 方块模型原本的 tint（草、树叶等）会先应用，再乘上你给的颜色；
- 特殊模型（箱子、旗帜等）没有普通模型部件，会回退默认渲染路径，**不会被染色**；
- `renderLevelItem`（物品）暂不支持整体染色。

## 渲染状态

没有全局颜色/RenderType 状态：需要自定义层级时直接在 `renderSingleBlock(...)` 里传 RenderType（见上文「渲染层级」）。

## 3D 变换

| 方法 | 说明 |
|---|---|
| `pushPose()` / `popPose()` | 保存 / 恢复 pose |
| `translate(x, y)` / `translate(x, y, z)` | 平移 |
| `scale(x, y)` / `scale(x, y, z)` | 缩放 |
| `mulPose(quaternion)` | 应用四元数旋转 |
| `rotationDegreesX/Y/Z(degrees)` | 绕轴旋转（角度制） |
| `getPoseStack()` | 直接拿 `PoseStack` |

## 其它

| 方法 | 说明 |
|---|---|
| `getStage()` | 固定返回 `"submit"`（26.1.2 无阶段区分） |
| `getPartialTick()` | 当前帧 partial tick |
| `getLevelRenderer()` | `LevelRenderer` 实例 |
| `getCameraPosition()` | 相机世界坐标 |

## 示例：在固定位置画方块与物品

```js
RenderJSEvents.onLevelRender(event => {
  const poseStack = event.getPoseStack()
  event.pushPose()
  event.transformerCamera(poseStack)
  event.transformerToBlockPose(poseStack, new BlockPos(0, 64, 0))

  // 全亮的钻石块
  event.renderSingleBlock(Blocks.DIAMOND_BLOCK.defaultBlockState(), poseStack)

  // 方块上方转动的物品
  event.pushPose()
  event.translate(0.5, 1.2, 0.5)
  event.rotationDegreesY(event.getPartialTick() * 60)
  event.renderLevelItem(Item.of('minecraft:diamond'), poseStack)
  event.popPose()

  event.popPose()
})
```

## 示例：跟随实体画东西

```js
RenderJSEvents.onLivingPreRender(event => {
  const state = event.getRenderState()   // EntityRenderState：含 x/y/z、光照、partialTick 等
  const poseStack = event.getPoseStack()

  event.pushPose()
  event.transformerCamera(poseStack)
  event.translate(state.x, state.y + state.boundingBoxHeight + 0.3, state.z)
  event.renderLevelItem(Item.of('minecraft:emerald'), poseStack, state.lightCoords)
  event.popPose()
})
```

## 渲染层级 / 穿过地形

26.1.2 没有 `RenderSystem.enableDepthTest()` 这类全局开关，**层级由 RenderType 使用的 RenderPipeline 里的
`DepthStencilState` 决定**。要让方块「穿过地形」画在最上层，需要给它一个禁用深度测试的 RenderType。

RenderJS 内置了两个这样的 RenderType：

| RenderType | 用途 |
|---|---|
| `RenderJSRenderType.TOP_LAYER_TARGET` | 方块模型，忽略深度，总是画在地形上方 |
| `RenderJSRenderType.TOP_LAYER_LINE_TARGET` | 线框/描边，忽略深度 |

```js
RenderJSEvents.onLevelRender(event => {
  const poseStack = event.getPoseStack()
  event.pushPose()
  event.transformerCamera(poseStack)
  event.transformerToBlockPose(poseStack, new BlockPos(0, 64, 0))

  const state = Blocks.DIAMOND_BLOCK.defaultBlockState()

  // 普通的、会被地形遮挡的方块
  event.renderSingleBlock(state, poseStack)

  // 穿过地形、永远可见的方块
  event.renderSingleBlockWithType(state, poseStack, RenderJSRenderType.TOP_LAYER_TARGET)

  // 穿过地形的描边
  event.renderHitOutlineWithType(state, poseStack, RenderJSRenderType.TOP_LAYER_LINE_TARGET)

  event.popPose()
})
```

### 原理与自定义

RenderJS 的两个内置 RenderType 由自定义 pipeline 支撑（在 `RegisterRenderPipelinesEvent` 里注册）：

```java
RenderPipeline pipeline = RenderPipeline.builder(RenderPipelines.ENTITY_SNIPPET)   // 方块/实体都用的 entity 着色器
        .withLocation(Identifier.fromNamespaceAndPath("mymod", "pipeline/block_no_depth"))
        .withShaderDefine("ALPHA_CUTOUT", 0.1F)
        .withSampler("Sampler1")                                                    // overlay
        .withDepthStencilState(new DepthStencilState(CompareOp.ALWAYS_PASS, false)) // 关闭深度测试/写入
        .build();

RenderType type = RenderType.create("mymod:block_no_depth",
        RenderSetup.builder(pipeline)
                .withTexture("Sampler0", TextureAtlas.LOCATION_BLOCKS)              // 方块图集
                .useLightmap()
                .useOverlay()
                .setOutline(RenderSetup.OutlineProperty.NONE)
                .createRenderSetup());
```

常见层级需求与做法：

| 需求 | DepthStencilState |
|---|---|
| 正常（被遮挡） | `DepthStencilState.DEFAULT`（`LESS_THAN_OR_EQUAL` + 写深度） |
| 永远画在最上层（穿过地形） | `new DepthStencilState(CompareOp.ALWAYS_PASS, false)` |
| 略微前置、避免与同位置几何 z-fighting | `LESS_THAN_OR_EQUAL` + 负 depth bias（`new DepthStencilState(CompareOp.LESS_THAN_OR_EQUAL, false, -1F, -10F)` 之类） |
| 只画在已有几何前面（不写深度） | `new DepthStencilState(CompareOp.LESS_THAN_OR_EQUAL, false)` |

如果 RenderJS 内置的两个不够用，可以按上面方式自己注册 pipeline + RenderType，再通过
`renderSingleBlockWithType(state, poseStack, yourRenderType)` 使用；RenderType 是单个 `RenderType` 实例，
可以在脚本里保存/传递。

注意：

- 穿过地形的几何仍然受**批次排序**影响：同帧内 RenderJS 能保证它比普通地形晚提交，但它与其他透明/特殊批次
  的相对顺序由引擎按 RenderType 排序；
- `renderSingleBlockWithType(..., renderType)` 对**普通方块模型**有效；箱子、旗帜等「特殊模型」没有普通模型部件，
  会自动回退到默认渲染类型（因此不会穿过地形）。

## 注意

- 世界渲染是**提交式**的：几何会进入当前帧的渲染队列，按 RenderType 排序，不能保证与调用顺序一致的绘制顺序；
- `onLevelRender` 一帧只触发一次，`onLivingPreRender/Post` 每个可见实体各触发一次；
- 不要在回调里做重计算；需要每帧变化的量用 partialTick/时间推导即可；
- 世界渲染没有 `MultiBufferSource`/立即模式 API，旧脚本里的 `RenderJSRenderSystem` 调用在新版本全部是 no-op。
